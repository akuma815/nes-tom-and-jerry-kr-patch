# 타이틀 로고 조사

대상은 `config/source_rom.json`의 일본판 한 개다. mapper 4, PRG 128KiB, CHR 128KiB, trainer 없음, 수평 미러링이다. 다른 리비전에 오프셋을 전용하지 않는다.

## 현재 확정 범위

- 로고 타일맵: 파일 `0x2023C..0x202C2`, 27×5 셀. CHR ROM에 저장된 데이터다. 메인 화면의 NT 열 2..28·행 4..8, 도입 화면의 열 2..28·행 18..22와 일치한다.
- Tuffy 타일맵: 파일 `0x202C3..0x2032E`, 27×4 셀. 로고와 패턴 `$17`, `$1E`를 공유한다.
- 실제 로고 CHR 뱅크: 파일 `0x2C810`, NES 2bpp, 타일당 16바이트. `$01..$44`가 원래 로고 패턴이며 Tuffy 공유 패턴을 포함한다.
- 새 로고는 `$01..$42`에 고유 타일 66개를 배치한다. 원본 `$17`, `$1E` 패턴을 `$43`, `$44`로 보존하고 Tuffy 참조 세 군데를 바꾼다. Tuffy 디코드 픽셀 동일성을 빌드에서 검사한다.
- 로고 속성·팔레트·화면 위치와 코드/헤더는 그대로 둔다. 밝은 기존 인덱스를 선택해 어두운 갈색으로 표시되는 획을 피한다.

## 래스터 증거

프레임 종료 메모리만으로 활성 로고 뱅크를 판정하면 잘못된다. 메인 화면 종료 시 PPU `$0000`은 파일 `0x2B010`이지만 로고를 그릴 때는 `0x2C810`이다. `$8000..$8001` 쓰기 콜백으로 전환 시점의 PPU 상태를 수집했다. 콜백은 쓰기 직전 상태이므로 이후 쓰기 결과와 구분한다.

- `qa/title_004/original_survey_v2/raster_3599_2_ppu.bin`: 메인 로고 활성 뱅크.
- `qa/title_004/original_survey_v2/raster_299_149_ppu.bin`: 도입 하단 로고 활성 뱅크.
- 패치본 같은 이름의 덤프는 최종 ROM의 `0x2C810..0x2D00F`와 일치한다.
- 최종 타일맵과 PPU 적재 결과, 실제 화면 변화가 함께 확인됐다. CPU 로더 전체의 완전한 역공학을 주장하지 않는다.

## 생성 자산과 변환

`assets/title/title_kr_ai_001_generated.png`는 원본 로고 PNG를 참조해 `image_gen.imagegen`으로 생성한 `톰과 제리` 이미지다. 생성 호출의 노란 실루엣을 빌드에서 밝기 임계값 120으로 마스크화하고 bbox `(98,121,1962,614)`를 자른다. LANCZOS로 160×32 변환, 임계값 128 적용, 216×40 캔버스 `(28,4)`에 배치한다. 원본의 셀별 팔레트 선택에 맞춰 2bpp 인덱스를 지정한다. 주 빌드 입력은 생성 PNG이며 임시 변환 PNG는 입력이 아니다.

## 보존한 실패와 교정

- `001`: 종료 시점 뱅크를 로고 뱅크로 오판했다. 시각 QA에서 기각했다.
- `002`: 활성 뱅크는 맞았으나 일부 색이 어둡고 Tuffy 공유 타일이 보존되지 않았다. 채택하지 않는다.
- `003`: 밝은 색과 66타일 변환은 확보했으나 Tuffy 공유 참조 보존이 없었다. 회귀 검사에서 기각했다.
- 초기 입력 비교에서는 원본만 DB의 패드 자동 설정을 받았다. 최종 QA는 DB 자동 설정을 끄고 양쪽에 NES 패드 두 개와 NTSC를 명시했다. 입력을 못 받은 초기 패치본을 게임 진행 실패 증거로 사용하지 않는다.
- emucap은 호환 바이너리 부재로 `launched:false`였다. 최종 실행 QA는 Mesen 2.2.1의 독립 testRunner로 수행했다.

Mesen API 참고: [공식 Lua 문서](https://github.com/SourMesen/Mesen2/blob/master/UI/Debugger/Documentation/LuaDocumentation.json). 현재 문서는 바뀔 수 있으므로 실행에 사용한 로컬 Mesen 버전과 해시를 인계 문서에 고정했다.
