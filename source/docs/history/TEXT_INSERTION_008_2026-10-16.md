## 삽입 방식

원본에서 004와 005를 재현한 후, 원본에 대한 최종 쓰기 9개를 검증한 통합 결과를 만든다. 기존 ROM을 수동으로 덧대는 방식은 빌드 입력으로 사용하지 않는다. 헤더·크기·실행 코드는 바꾸지 않았다. 005 대비 실제 변경은 1,836바이트다.

- PRG 인라인 범위는 파일 `0x04342..0x043AE`, `0x043BD..0x04405`, `0x04414..0x04452`, `0x045A5..0x04611`이다. 각 마지막 `$80`과 뒤 코드의 주소를 유지한다. 남는 길이는 첫 글자 좌표를 설정하기 전의 중복 속성/좌표 명령으로 소비한다.
- 폰트는 파일 `0x2A820..0x2AE2F`, 기존 8×8 타일 `$01..$61`을 사용한다. 공백 포함 98종 / 허용 128종이다. 공백 `$00`과 `$62..$7F`는 원본 그대로다. 일본어 18행의 소비자를 한국어로 교체한 범위이며, 다른 간접 소비자가 전혀 없다는 전수 증명은 아니다.
- 제공된 `Galmuri7_8x8.png`에서 U+AC00 순서·64열의 8×8 셀을 사용한다. 필요한 한글 93종을 같은 버전 TTF의 8px, y=-1 렌더와 픽셀 대조했다. 네 문장부호도 같은 TTF를 사용한다. 빈 글자·동일 마스크 충돌·셀 밖 잉크는 0이다. 폰트 출처는 [Galmuri 공식 저장소 v2.40.3](https://github.com/quiple/galmuri/tree/v2.40.3)이며 OFL 원문을 함께 보관했다.
- 원래 일본어와 같은 잉크 색 번호 3을 사용한다. 006의 색 번호 1은 도입부에서 회색, 엔딩에서 어둡게 표시되어 제외했다. 007에서 수정했다.
- 내용 18행은 모두 유지했다. 첫 페이지 둘째 문장을 두 화면 행으로 나눠 총 19행으로 표시한다. 초안의 단어·문장부호는 변경하지 않았다.
- 008에서는 두 번째 페이지 둘째 화면 행을 원래의 17셀 영역까지 공백으로 채운다. 007은 짧아진 문장 때문에 공유 속성 영역의 갱신이 달라져 제리 볼 4픽셀 색이 달랐다. 두 공백은 원래 텍스트 영역의 빈 셀을 쓰며, 해당 16×16 팔레트 갱신 범위를 복구한다. 008의 그림 영역은 005와 동일하다.

## 검증 결과와 한계

**정적·빌드/패치**: 지원 원본 식별, 원문 카탈로그/초안 해시, 선택 문구 보존, 98종 문자 예산, 97종 비공백 마스크의 비어 있지 않음·서로 다름, 한글 93종의 시트/TTF 일치, NES 2bpp 역변환, 스크립트 재해석·좌표·종료 위치, Expected Write·비대상 바이트·헤더/크기, IPS 적용 동일성을 통과했다. 원본용 적용 도구도 별도 출력에 적용해 현재 ROM과 같은 해시를 확인했다.

**에뮬레이터**: 별도 Mesen 2.2.1 testRunner를 사용했다. 실행 파일 SHA-256은 `a4a18b59c5d1bcaaedd1ad59b48daec89a3a710f0581765c9da7f5029e5f0084`이며 설정·명령·ROM 해시는 각 `run.json`과 `emulator_settings.json`에 있다. 사용자의 실행 중인 Mesen은 조작하지 않았다. emucap 실행 검증은 하지 않았다.

- 정상 콜드 부트에서 세 도입 페이지를 확인했다. 프레임 1800/2100/2700의 모든 행이 PPU 타일맵·활성 폰트와 일치한다. 총 잉크 1,179/872/699픽셀을 실제 캡처와 대조했고 잘림·가림은 0이다.
- 엔딩은 프레임 1302에 CPU 실행 위치를 기존 도입 호출 `$A32F`에서 원래 엔딩 설정 `$A57F`로 한 번 돌린 **진단 실행**이다. 개입 당시 PRG 매핑 오프셋 `$432F`를 확인하고, 프레임 1306에 원래 엔딩 텍스트 호출 `$A592` 진입을 기록했다. ROM은 수정하지 않았다. 첫 도입과 같은 뱅크/초기화 상태를 이용한 표시 경로 검사이며 정상 플레이의 이벤트·보스·엔딩 진입 조건을 증명하지 않는다.
- 진단 엔딩의 6행은 프레임 1800에서 PPU·활성 폰트와 일치했고, 잉크 1,138픽셀 모두 표시됐다. 엔딩 캡처의 타이틀/색 배치는 같은 개입을 한 기존 005와 동일하다. 정상 엔딩의 연출 적합성은 미확인이다.
- 위 네 페이지의 팔레트·OAM은 005와 같으며 원문/번역 텍스트 셀을 합친 범위 밖은 픽셀 단위로 같다. 관찰된 화면 좌표 보정은 도입 (+4,0), 진단 엔딩 (-4,-19)이며 실행 캡처의 소비 결과로 확인했다.
- 콜드 부트의 프레임 300/900/3600/4200/4800/5400은 기존 005와 화면 전체가 같다. 글자 수 변화로 도입 글자 출력과 페이지 전환 시점 일부가 달라지지만 이후 타이틀로 복귀한다.
- 프레임 3600에 START를 누른 별도 실행의 6개 프레임에서 스테이지 안내·첫 스테이지 표시까지 기존 005와 화면/OAM이 같다. 짧은 진입 검사이며 전체 플레이 검증은 아니다.

**직접 시각 확인**: 최종 실행 화면 4페이지를 모음 PNG로 열어 글자·받침·문장부호·줄바꿈·초상과의 간격을 확인했다. 자동 잉크 검사와 별개로 기록한다. 사람의 최종 폰트 미감 평가는 아직 받지 않았다.

**미실시**: 정상 플레이를 통한 엔딩 도달, 전 스테이지·간접 텍스트 소비자 전수 확인, 전체 플레이, 실기, 다른 에뮬레이터, 오디오 검증, 공개 패키지 QA. 007의 리셋 조사 증거를 보존했지만 008의 리셋 실행으로 보고하지 않는다.

## 재현 명령

프로젝트 루트에서 Python 3.12 / Pillow 12.3.0 환경을 사용한다. 기존 생성형 타이틀 원본과 고정 폰트 입력을 소비하며 생성형 서비스를 다시 부르지 않는다.

```powershell
python .\scripts\build_text_kr.py
python .\scripts\apply_text_008.py --source ".\original\rom\Tom & Jerry (Japan).nes" --output ".\qa\text_008\patch_apply\Tom_Jerry_KR_text_008.nes"
python .\scripts\verify_text_qa.py
```

`verify_text_qa.py`는 보존된 실행 증거를 검사한다. 새 실행을 재현할 때는 이전 증거를 덮어쓰지 않는 새 `--out` 경로를 사용하고 검증기의 입력 경로를 명시적으로 갱신한다.

```powershell
python .\scripts\run_capture.py --rom .\build\text_kr_008\Tom_Jerry_KR_text_008.nes --out .\qa\text_008_recheck\normal --frames 300,900,1500,1800,2100,2400,2700,3000,3300,3600,4200,4800,5400
python .\scripts\run_capture.py --rom .\build\text_kr_008\Tom_Jerry_KR_text_008.nes --out .\qa\text_008_recheck\ending_diagnostic --frames 1500,1600,1700,1800,1900,2100,2400,2700,3000 --ending-entry
python .\scripts\run_capture.py --rom .\build\text_kr_008\Tom_Jerry_KR_text_008.nes --out .\qa\text_008_recheck\gameplay_start --start 3600 --frames 3600,3630,3900,4200,4800,5400
```

기준 실행은 `qa/text_007/baseline_normal`, `baseline_gameplay`, `qa/text_006/baseline_ending`이다. 모두 같은 Mesen/설정과 005 ROM 해시에 연결된다. 후보 006·007과 그 실패 증거도 보존했다. 삭제한 파일은 없다.
