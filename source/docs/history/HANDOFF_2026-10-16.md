## 004 에뮬레이터 실행 검사 — 이전 검증 기록

실제 사용: **Mesen 2.2.1**, 제품 버전 `2.2.1+4b8a196e299b3de297b204fd1208d2981562c89b`.

실행 파일 SHA-256: `a4a18b59c5d1bcaaedd1ad59b48daec89a3a710f0581765c9da7f5029e5f0084`.

`H:\Mesen\Mesen.exe`에서 필요한 파일을 `tools/mesen_qa/`로 복사해 headless `--testRunner`를 실행했다. 기존 사용자 Mesen 프로세스·설정은 조작하지 않았다. 최종 비교는 NTSC, RAM 0 초기화, 정렬 랜덤화 끔, NES 패드 두 개, 입력/게임 DB 자동 설정 끔으로 양쪽 설정을 맞췄다. 각 실행 폴더의 `emulator_settings.json`, `run.json`, `stdout.log`, `complete.txt`를 보존했다.

- 무입력 콜드 부트: 120/300/600/900/1100/1800/2400/3600프레임.
- 3600프레임 START 2프레임 입력: 3600/3650/3750/3900/4200/4500프레임.
- 같은 입력 후 4600프레임 리셋: 4500/4600/4900/5200/5800/8200프레임.
- 총 20쌍 비교 통과. 로고 밖 변경 픽셀 0개, 10쌍은 전체 화면 픽셀 동일.
- 모든 20쌍에서 내부 RAM·OAM·팔레트·속성 데이터 동일.
- 로고 NT 적재 결과가 최종 타일맵과 같고, 래스터 전환 시점 활성 CHR이 최종 ROM과 같음을 확인했다.
- 비교 이미지와 저작권/리셋 화면을 직접 열어 `톰과 제리` 판독, 그림·Tuffy·주변 문구 보존을 확인했다.

**emucap 검증은 수행하지 못했다.** bootstrap/launch에서 호환 어댑터 바이너리 부재로 `launched:false`였다. 위 결과는 독립 Mesen testRunner 실행 증거다.
